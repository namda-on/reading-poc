# 리딩 모드 POC 설계

## 배경 / 목적

리스닝 학습은 "표현이 트리거가 되어, 배운 표현이 실제 대화 맥락에서 어떻게 쓰이는지 실시간으로 처리하며 체득하는" 훈련이다.
문제는 리스닝이 불가능한 환경(소리를 못 듣는 상황)에서는 이 콘텐츠를 그대로 버려야 한다는 점이다.

핵심 아이디어: **리스닝 = 통제 불가능한 실시간 해석 훈련**이고, 이걸 소리 없이 리딩으로 재현한다.
일반 리딩과 리스닝의 결정적 차이는 **읽는 사람이 페이스를 통제할 수 있는가**이다.
일반 리딩은 눈이 되돌아가고(regression) 앞서 읽을(skip ahead) 수 있지만, 리스닝은 불가능하다.
따라서 리딩으로 리스닝을 재현하려면 **되돌아가기·미리보기를 물리적으로 차단**해야 한다.

이 POC는 그 경험을 빠르게 만들어 보고, **더 나은 학습 경험의 방향**(청크 단위·창 크기·속도)을 주관적으로 탐색하기 위한 도구다.

## 범위

이 POC는 **주관적 체험용 웹 프로토타입**이다. 정량 실험(정답률 로깅·조건별 비교)은 범위 밖.

- 콘텐츠: **스티브 잡스 코스(courseSeq 25)의 A2(level 2) 대화 22개 전부** + 코스/토픽 선택 화면
- 대화 데이터 출처: `~/sayvoca/conversation-agent/server.sqlite` (일회성 추출 → 정적 fixture)
- 문제: 대화당 한국어 내용이해 객관식 2문항 (미리 생성)

### 안 하는 것 (YAGNI)

- 정답률·행동 로그 서버 저장
- 방식 2(전광판/리듬게임식 흘려보내기) — 후속 실험으로 미룸
- 런타임 sqlite 접근, 런타임 LLM 호출
- A2 외 레벨, 스티브 잡스 외 코스, 로그인

## 노출 메커니즘 (경험의 심장부)

말풍선은 **문장 전체 크기만큼 미리 확보**된다.
그 안에서 **N개짜리 창(window)이 청크의 실제 위치를 따라 좌→우로 미끄러지며** 노출한다.

- 아직 안 온 청크, 지나간 청크: **빈 공백**으로 자리만 유지 (글자 없음)
- 지금 "켜진" 구간: N개 청크
- 문장 길이·줄바꿈이 드러나는 것(길이 노출)은 **허용**한다. 위치(공간) 맥락을 살리기 위함.

이렇게 하면 문장 내 위치 맥락은 유지되면서도, 미래·과거 청크가 가려져 되돌아가기·미리보기가 차단된다.

### 실험 축 3개

1. **노출 단위**: 단어 ↔ 청크(의미 단위) 토글
2. **창 크기 N**: 1(완전 휘발) ~ N(슬라이딩 윈도우)
3. **슬라이딩 속도**: 길이 비례. 청크 dwell = `max(최소값, 단어수 × 기본ms)`. 슬라이더가 기본ms 조절.

## 아키텍처

Vite + React + TypeScript SPA. `conversation-agent/web`와 동일 스택. 서버 의존 0(정적 fixture).

### 1. 콘텐츠 fixture — `src/data/steveJobs.json`

`server.sqlite`에서 일회성 추출 스크립트(`scripts/extract.ts`)로 생성 후 커밋한다.

- 코스/토픽 목록 (선택 화면용)
- 대화별 스크립트 배열: `{ seq, speaker: 'A'|'B', english, translated, hint?, words }`
  - `words`: tagList의 `{s, e}` 오프셋에서 뽑은 단어 토큰 `{ text, start, end }[]`
- 대화별 퀴즈: 한국어 내용이해 MCQ 2문항 `{ question, options[], answerIndex }[]`

추출 시 tagList 파싱으로 단어 경계가 공짜로 확보된다. 퀴즈는 추출 단계에서 미리 만들어 fixture에 함께 저장한다.

### 2. 청커 — `src/lib/chunk.ts` (순수 함수)

입력: 문장 문자열 + 단어 토큰 → 출력: `{ text, start, end }[]`

- `word` 모드: tagList 단어 토큰을 그대로 반환
- `chunk` 모드: 규칙 엔진
  - 접속사·to부정사·전치사 **앞에서** 끊는다
  - 고정표현 화이트리스트(`a lot of`, `want to`, `in front of`, `the same as` 등)는 쪼개지 않는다
  - POC 수준의 소형 규칙셋 (전면적 POS 태깅은 하지 않음)

청크 경계는 설정(N·속도)과 무관하므로 대화 로드 시 단위별로 한 번만 계산한다.

### 3. 노출 엔진 — `src/hooks/useSlidingReveal.ts`

청크 배열 + 설정 `{ windowSize N, baseMsPerWord }`을 받아, 시간축으로 "지금 보이는 청크 인덱스 집합"을 방출한다.

- 청크 `i`는 자기 순서에 켜지고, 청크 `i+N`이 켜질 때 꺼진다
- `dwell(i) = max(MIN_DWELL, wordCount(i) × baseMsPerWord)`
- play / pause / replay 제어 제공
- 타이머 정리(cleanup)로 언마운트·리플레이 시 누수 방지

### 4. 말풍선 렌더러 — `src/components/DialogBubble.tsx`

문장 전체를 자연스러운 흐름의 청크 `span`으로 배치한다(실제 줄바꿈·길이 그대로).

- 보이는 창의 청크: `visibility: visible`
- 나머지(미래·과거) 청크: `visibility: hidden` → 자리(공백)는 유지되고 글자만 사라짐

`visibility: hidden`은 레이아웃 박스를 유지하므로 "빈 공백 + 길이 노출 + 위치 맥락"이 정확히 구현된다.
화자 A/B는 좌우 정렬·색으로 구분한다.

### 5. 세션 플레이어 — `src/components/ReadingSession.tsx`

대화 스크립트를 순회한다.

- 각 스크립트마다 노출 엔진 실행 → 끝나면 다음 말풍선 자동 등장
- 지난 말풍선은 채팅에 **빈 껍데기로 잔류**한다(되돌아 읽기 불가 유지)
- 재생 버튼: 대화 전체를 처음부터 리플레이 (문제 풀기 전 1회)
- 대화 종료 → 퀴즈로 전환

### 6. 설정 패널 — `src/components/Settings.tsx`

노출 단위(단어/청크)·창 크기 N·기본 속도를 **실시간 조절**한다. 조절 즉시 다음 노출부터 반영.

### 7. 퀴즈 — `src/components/Quiz.tsx`

한국어 내용이해 MCQ 2문항. 답 선택 후 정답·해설 피드백.
퀴즈 중에는 대화를 표시하지 않는다(리플레이로만 접근) → 청크 노출이 힌트가 되는 문제를 회피한다.

### 8. 내비게이션 — `src/App.tsx`

코스/토픽 선택 → 세션 → 퀴즈 → 결과 화면.

## 데이터 흐름

```
fixture 로드
  → 토픽 선택
  → chunk.ts (단위별 분할, 대화당 1회)
  → useSlidingReveal (설정대로 타임라인 생성)
  → DialogBubble (창 안 청크만 visible)
  → 대화 종료
  → Quiz
  → 결과
```

## 유닛 경계 요약

| 유닛 | 하는 일 | 의존 |
| --- | --- | --- |
| `chunk.ts` | 문장 → 청크 배열 (단어/규칙) | 없음 (순수) |
| `useSlidingReveal` | 청크+설정 → 보이는 인덱스 집합(시간축) | 타이머 |
| `DialogBubble` | 청크+보이는 집합 → 말풍선 렌더 | `chunk` 결과 |
| `ReadingSession` | 대화 순회·자동 진행·리플레이 | 위 셋 |
| `Quiz` | MCQ 출제·채점 | fixture 퀴즈 |
| `App` | 화면 전환 | 전부 |

각 유닛은 입력·출력이 명확하고 독립적으로 이해·테스트 가능하다.
